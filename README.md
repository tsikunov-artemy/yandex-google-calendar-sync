# Яндекс Календарь → Google Calendar

Сервис поддерживает в Google копию рабочего календаря Яндекса. Подходит для приложений, которые умеют брать встречи только из Google. Календарь Яндекса подключается по CalDAV, календарь Google — через Calendar API.

При переносе одной встречи из повторяющейся серии сервис находит в Google тот же экземпляр по его первоначальному времени и обновляет его с сохранением Google ID. В описание попадают ссылки Телемоста. Перед удалением связанной записи сервис проверяет источник в Яндексе.

В рабочие часы пауза между циклами составляет одну минуту, в остальное время — пять минут. Раз в десять минут во время работы сервиса дополнительно сверяются ближайшие 14 календарных дней. Поля `WORK_HOURS_START` и `WORK_HOURS_END` задают часы в UTC, по умолчанию с 05 до 18 по будням.

[Как работает синхронизация](ARCHITECTURE.md) — путь встречи от Яндекса до Google, обработка переносов, диагностика и ссылки на код и тесты.

## Запуск

Понадобятся Docker с Compose на сервере и `uv` на компьютере с браузером для первого входа в Google. Скачайте проект на компьютер. Выполняйте команды из корня проекта.

### На компьютере

1. Подготовьте конфигурацию для первого запуска.

   ```sh
   mkdir -p credentials
   cp .env.example .env
   ```

2. В `.env` укажите email Яндекса в `YANDEX_USERNAME`, пароль приложения типа «Календарь» в `YANDEX_PASSWORD` и точное название исходного календаря в `YANDEX_CALENDAR_NAME`. [Создать пароль приложения Яндекса](https://id.yandex.ru/security/app-passwords)
3. Выберите отдельное имя для Google-копии в `GOOGLE_CALENDAR_NAME`. По умолчанию это `Yandex Calendar`. Сервис использует существующий календарь с таким именем или создаст новый.
4. Включите Google Calendar API в своём проекте Google Cloud и создайте OAuth-клиент типа **Desktop app**. Если приложение в режиме Testing, добавьте свой Google-аккаунт в список тестовых пользователей. Скачайте JSON клиента в `credentials/google_credentials.json`. [Google Cloud Console](https://console.cloud.google.com/)
5. Запустите команду ниже и войдите в Google-аккаунт, в котором хотите видеть встречи. Скрипт сохранит токен в `credentials/token.json`.

   ```sh
   uv run --locked python scripts/setup_google_oauth.py
   ```

### На сервере

Разместите проект на сервере. Перенесите туда `.env` и папку `credentials/` по защищённому каналу, например через SSH. Для обычной установки Docker на Linux подготовьте каталоги из корня проекта. Контейнер работает с UID 1000 и записывает базу в `data/`, а обновлённый токен в `credentials/token.json`.

```sh
mkdir -p data
sudo chown -R 1000 data credentials
sudo chmod 700 data credentials
sudo chmod 600 credentials/google_credentials.json credentials/token.json
chmod 600 .env
docker compose up -d --build
docker compose logs -f calendar-sync
```

Дождитесь записи `sync.completed` с нулём в поле `errors`. Для проверки создайте в Яндексе встречу без гостей на завтра. Когда она появится в Google-копии, перенесите её в Яндексе на другое время. После синхронизации в Google должна остаться одна встреча с новым временем.

SQLite-база в `data/` хранит привязки записей к Google ID и нужна при переносе установки на другой сервер.

## Где хранятся учётные данные

| Файл | Содержимое | Кто его читает |
|---|---|---|
| `.env` | Логин Яндекса, отдельный пароль приложения и выбранные календари | Docker Compose передаёт параметры процессу при запуске. Образец для копирования — `.env.example`. |
| `credentials/google_credentials.json` | Параметры OAuth-клиента Google, в том числе `client_id` и `client_secret` | Скрипт первоначальной авторизации. |
| `credentials/token.json` | Токен доступа Google и refresh token для его продления | Скрипт создаёт файл после входа. Сервис читает его и сохраняет обновлённые данные. |
| `data/` | SQLite с привязками событий, журнал синхронизации и возможные логи с деталями встреч | Сервис использует каталог для сохранения состояния между запусками. |

`docker-compose.yml` подключает `credentials/` и `data/` при запуске контейнера. Перед публикацией изменения можно проверить из корня репозитория:

```sh
git check-ignore --no-index -- .env credentials/google_credentials.json credentials/token.json data/sync.db
git ls-files -- .env credentials/ data/ logs/
git diff --cached --name-only
```

Первая команда должна перечислить все четыре пути. Вторая должна вернуть пустой результат, включая после подготовки коммита. Последняя покажет перечень подготовленных изменений.

## Как пользоваться

Редактируйте рабочие встречи в Яндексе или в клиенте, подключённом к нему по CalDAV. Интеграции подключайте к Google-копии. Поддерживаемый сценарий этой версии — Яндекс → Google. Обратная синхронизация в коде экспериментальная.

## Проверка

```sh
uv run --locked pytest -q
```

Тесты используют вымышленные события и имитацию API. Рабочие учётные данные для них не нужны.
